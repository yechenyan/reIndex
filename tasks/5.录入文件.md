


## 原始请求

 先看下 wiki， 了解现在项目已经做了什么功能了。
目前已完成：
reIndex 标准
reIndex 上传数据库
 搜索

 现在要做一个重要的工作，从 raw 变成 reIndex。

 我的想法是，用户在 AI agent 里触发这项工作。
 提供一个 cli 叫足 rei
 AI agent 运行，适当的时候可以使用 cli
 可以考虑 coco index 或者其他的一些东西进行增量分析。

 loom 是我之前做的实验项目，你可以参考
 table_demo 是我专门做的解析 PDF 的，你也可以参考。

 我想的是针对不同的文件用不同的解析器， 解析器可以像流水线一样工作， 用户可以方便的给一些文件定制化解析器。
关于文件的ID，增量处理可以考虑 coco index


另外需要考虑一些文件是无法用这个 cli 的通用能力解决的，必须要想一个自定义解决的方案，我想的策略：
1. 直接用其他工具生成 reIndex，但这个无法保证质量
2. 做一些插件给 rei，但做插件麻烦，并且什么时候用插件，什么时候不用插件
3. 让用户自己处理生成 content, node.md 用 rei 生成
4. 让其他工具做初步生成再调用 rei 最后处理，但感觉不好衔接双方的格式
5. 多做一层呢， source 和 reIdnex 中间加一层， 自定义的方式写把 source 处理成中间层，再用cli 转成 reIndex

目前我没找到合适的思路
