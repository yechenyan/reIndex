## 实施记录

- 初始发行目标是 PyPI 包 `reindex-cli`；人工复核后，canonical distribution 改为 `reindex`，CLI 固定为 `rei`。
- 参考 Loom 的本地单入口发布脚本，并补上 clean-tree 门禁、Twine 检查和成品 wheel 隔离安装验收。
- 消除运行时版本双源，CLI 从已安装 distribution metadata 读取版本。
- 用户主路径简化为 `init → inspect → scan → push → search/get`；`check` 保留为改卡后或 CI 的独立验收。
- `testbase/test4-all` 在临时副本中由子 agent 使用成品 wheel 完整验收，没有覆盖工作区已有改动。

## 结果

- `reindex-cli 0.3.0` 已发布到 PyPI：<https://pypi.org/project/reindex-cli/0.3.0/>。
- 发布脚本会检查 clean worktree、回滚失败的版本与 `uv.lock`、运行 CLI 回归、构建 wheel/sdist、执行 Twine 检查、从 wheel 隔离安装并验证 Python API、`rei` 和 bundled skills。
- PyPI 发布后已从公网索引重新安装，`rei --version` 为 `0.3.0`，`reindex --help` 正常。
- 子 agent 用最终 wheel 和 `test4-all` 临时副本完整跑通 `init → inspect → scan → check → push → pull → search → get ×2`。
- 验收结果为 7 Nodes、2 Sources、16 Resources、1176 SearchUnits；pull 只有 7 个 `.node.md` 和 `.rei/remote.json`；search 返回 3 条；get 为 `download → cache`。

## 子 agent 反馈与优化

- 首个候选的 `--version` 会导入 Docling，冷启动很慢；改成按命令延迟加载后，本机从约 7.24 秒降至约 0.15 秒。
- 首个候选首次 `inspect` 为 42.58 秒且无进度；PDF 页数检查改用轻量 PDFium 后，最终 wheel 的首次 `inspect` 为 0.61 秒，约快 70 倍，完整复验通过。
- 当前首次 `scan` 仍可能因 Docling 模型加载耗时且输出偏底层；后续可增加产品化进度提示。
- CLI 当前安装 102 个依赖并包含 Torch；后续可评估把 PDF parser 拆成可选 extra，但不阻塞本次发布。
- `init` 的 skills 输出可进一步显式标注 global/project scope；CLI 与 server 版本之外也可显示协议兼容版本。

## 发行名称调整

- 人工反馈希望像 Loom 一样，由一个发行包同时承载 Python package 与 CLI。
- 从 `0.3.1` 起 canonical PyPI distribution 改为 `reindex`；安装名大小写不敏感，`reIndex` 与 `reindex` 等价。
- 稳定 Python namespace 是 `reindex`，首个公开入口为 `ApiClient` 和 `__version__`。
- CLI 命令固定为 `rei`；`reindex` 只作为 distribution 与 Python namespace。内部 `reindex_cli` 暂时保留为实现包。
- 已发布的 `reindex-cli 0.3.0` 不能原地改名，保留为旧发行记录，不再作为 canonical 安装名。
- `reindex 0.3.1` 已发布：<https://pypi.org/project/reindex/0.3.1/>；PyPI 已确认 wheel、sdist、`ApiClient` 文档和 Python 3.12 元数据。
- `reindex 0.3.2` 已发布：<https://pypi.org/project/reindex/0.3.2/>；移除容易混淆的 `reindex` console alias，并统一文档只使用 `rei`。
