## 当前实现

- 使用 ParadeDB `pg_search` BM25 covering index，删除 `tsvector`、`pg_trgm` 和进程内
  token/cosine 搜索。
- 使用 pgvector HNSW cosine ANN，按 active revision 的 embedding profile 隔离。
- lexical/hybrid 的 BM25 对 title、description、原文分别使用 4、2、1 倍权重。
- hybrid 在一个 SQL 中对 BM25 和向量候选执行 weighted RRF，并以 unit ID 稳定打破同分。
- `/v1/search` 默认 `hybrid`，支持候选数、Node/kind/path 过滤、两路权重、RRF K、
  cosine threshold 和每 Node 证据上限；不再支持 `auto` 或隐式降级。
- 响应返回最终 rank/score、BM25/cosine component score、channel rank 和逐字 Evidence。
- Render Blueprint 增加固定版本的 ParadeDB 私有服务、持久盘和自动 schema migration。

## 生产工程补强

- catalog 与 search 共用有界 PostgreSQL connection pool，不再每次查询建立 connection。
- archive 解包、Qwen document embedding 与 revision 写入改为同步 worker task，由
  FastAPI 在线程池执行，不再阻塞事件循环；替换 revision 建索引期间继续查询旧 active
  revision。
- `/v1/search` 增加绑定 query/filter/ranking/revision 的稳定 cursor、全局 rank、
  `candidate_count` 与 `next_cursor`。
- 新增 `reindex-server eval-search`，读取 JSONL 标注集并输出 Recall/MRR/NDCG 和
  mean/P50/P95 latency；`testbase/test1/search-eval.jsonl` 提供首批五条实例。
- weighted RRF 保持默认最终排序。Qwen3-Reranker-0.6B 是逐候选 cross-encoder 精排，
  当前不接入：现有数据规模和官方中文检索基准没有证明收益足以覆盖额外模型延迟。未来
  只有在标注集显示 Top-K/NDCG 显著提升后，才作为显式 profile 开启。
- 当前五条标注集实测：BM25 Recall@5 为 0.8，semantic/hybrid 为 1.0；hybrid 的
  `lexical_weight=0.5`、`semantic_weight=1` 相比 1:1 将 MRR 从 0.75 提高到 0.85、
  NDCG 从 0.812 提高到 0.886，因此作为当前默认值。warm hybrid P50/P95 约为
  112/153 ms；Qwen embedding 冷启动约 24 秒，改为应用启动阶段预热。
- 在线重复导入暴露并修复了 logical unit ID 跨 revision 主键冲突，以及失败事务错误切换
  active revision 的问题。数据库用 `revision_id + logical unit_id` 生成 BM25/embedding
  search key，API 继续返回稳定 logical ID；active revision 只在整个 catalog transaction
  成功后切换。实际重导入 84 units/84 embeddings 成功，期间 48 次 BM25 全部读取旧
  revision，最慢 70.4 ms，最终原子切换到新 revision。
- API 契约补充 typed search/grep response、OpenAPI request example 和字段说明；所有
  request model 禁止未知字段，collection/Node ID 按 UUID 校验。Evidence 的 `id` 统一改为
  `node_id`，避免与 unit ID 混淆。
- 所有 response 增加 `X-Request-ID`；JSON error 统一为
  `invalid_request`、`not_found`、`conflict`、`internal_error` envelope，schema validation
  包含 details。文档明确当前 import 是非持久后台线程，因此暂不提供虚假的 job ID/cancel
  契约。
