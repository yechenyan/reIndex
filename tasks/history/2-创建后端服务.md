## 结论

最终方案已写入 [`wiki/dev/backend-service.md`](../wiki/dev/backend-service.md)。摘要：

- collection 是隔离边界，ID 即根 Node 的稳定 ID；根 Node 是普通 `group` Node，并没有新
  的 `kind` 或不同内容格式。raw/resource 字节使用 SHA-256 去重后存入 S3-compatible 对象存储；
  PostgreSQL 只保存可由 package 重建的 canonical 投影与索引。
- raw 文件以 collection 内相对路径保存和下载，保留目录结构；raw 自身不索引，ReIndex
  导入依据 `raw://` 路径关联 raw 后才为 Node/CSV 建索引。
- 以不可变 `collection_revision` 导入并在 ready 后原子切换 current revision，保证失败导入不
  影响已上线的可查询版本。
- PostgreSQL 使用加权 GIN `tsvector` + `pg_trgm` 做全文/字面召回，`pgvector` HNSW 做
  固定 profile 的语义召回，hybrid 以 RRF 融合。
- 四种 `/search` mode 为 `lexical`、`semantic`、`hybrid`、`auto`；精确字面/正则是独立
  `/grep` 工具。每个结果必须可回到逐字 excerpt、Node 行范围、source hash 和页码。
- API 使用稳定动作路径，不在 URL path/query string 中放 collection、Node 或文件路径。
  上传接口收敛为 multipart `POST /v1/raw/upload` 与异步 `POST /v1/reindex/import`；状态使用
  JSON `POST /v1/collections/status`，不要求用户管理 import ID。配套 browse、get、下载和
  受限的 CSV DuckDB query API 也都由 JSON body 传标识符。初始 embedding profile 为服务端
  本地 `Qwen/Qwen3-Embedding-0.6B`，输出 1024 维；CSV 全文和行级向量都会建立。该模型
  适用于 8GB 以下内存的服务实例；更大 profile 必须在标注集评测后另行启用。页面视觉索引、
  reranker 和 query rewrite 留待后续评测。
