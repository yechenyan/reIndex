## 追加要求与确认方案

- CLI 使用 `push`、`pull`、`search`、`get`、`set-api`，并增加幂等 `init`。
- `init` 创建或复用本地 Collection 身份，并创建或更新 Agent skills；本次不下载教程数据。
- Collection 增加用户可读且服务端唯一的 `name`；UUID 只作为内部稳定身份。
- resource logical path 保持 Collection 内相对路径，由 Collection UUID 在数据库中隔离，不把 UUID 拼进 logical path。
- 保留本地 Node logical key 到稳定 UUID 的身份注册表；文件名调整为更明确的 `node-identities.json`。
- 后端使用一个同步、可破坏性变更的 `POST /v1/push`，一次接收 package ZIP 和 sources ZIP；本次不实现异步任务、版本、协作、增量上传或任务恢复。
- `POST /v1/pull` 下载只有 `.node.md` 的 Node tree；`POST /v1/get` 统一完成 path 解析和精确 resource 下载。
- `get` 依次复用完整本地 package、authoring source、SHA-256 缓存，最后才下载确切资源。
- 除单元测试外，必须完成三组流程模拟：`test2/reIndex` push、`test3-download` pull、复制 test2 数据到 `test4-all` 后跑完整流程。

## 实现结果

- CLI 升级到 `0.3.0`，加入 `init`、`rename`、`skills install/update`、`set-api`、`push`、`pull`、`search`、`get`。
- CLI wheel 内置 `reindex-create`、`reindex-scan`、`reindex-data` 三个 skills；更新只覆盖未被用户修改的托管副本，`--force` 可显式覆盖冲突。
- Collection 状态加入规范化 `name`，旧状态在下一次 `init` 时自动补写；rename 保持 Collection UUID 和 Node UUID 不变。
- Node 身份注册表改为 `.rei/node-identities.json`，读取时兼容已有 `.rei/identities.json`；logical key 到 UUID 的映射继续确保重新 scan 后 Node 身份稳定。
- 后端升级到 `0.2.0`，公开数据流程统一为同步 `POST /v1/push`、Node-only `POST /v1/pull`、`POST /v1/search`、精确资源 `POST /v1/get`；移除旧 create/upload/import/status/resolve/download 路由。
- `push` 一次接收 package ZIP 与 sources ZIP，要求 sources 与 Node cards 的全部 `raw://` 引用集合完全一致，并逐文件校验 SHA-256；成功后原子替换当前 Collection 数据。
- 服务端 Collection name 唯一；内部仍以 Collection UUID 隔离 Node、Resource 和 SearchUnit。Resource 唯一键为 `(collection_id, namespace, logical_path)`，logical path 保持 Collection 内相对路径，因此 Collection 改名不影响资源身份。
- `pull` 只生成完整 `.node.md` tree；`get` 按本地 package/本地 authoring source、SHA-256 cache、远端精确下载的顺序复用数据，并校验下载响应哈希。
- 文档已同步更新 README、CLI/Server README、overview、quickstart、setup、testing、architecture、backend service 与 HTTP API reference；旧命令和旧 HTTP 路由全文审计无残留。

## 与 Loom CLI 的最终对比

| 维度 | ReIndex 0.3 | Loom 当前实现 |
| --- | --- | --- |
| 用户入口 | `rei` 同时是本地编译与远端数据 CLI | `loomcli` 是终端 CLI，`loom ...` 另表示 Agent chat intent |
| 初始化 | `rei init` 创建/迁移 Collection 身份并安全安装或更新 skills，不带教程数据 | `loomcli init` 初始化 workspace、skills 与本地 Git，并默认支持教程数据 |
| 数据模型 | Collection → typed Node tree → source/content/assets，Node UUID 跨重新 scan 稳定 | workspace → dataset/file cards 与 manifests，以 logical path 和本地 Git revision 为中心 |
| 发布 | 一个同步全量 `push`，package 与确切引用的 sources 一次提交 | status → confirm → push，支持 revision/base revision、缺失 raw object 上传与冲突处理 |
| 拉取 | `pull` 只取 Node cards；`get` 精确取 card/source/content/asset/raw 并按 SHA 复用 | `pull` 拉 workspace；`pull-raw` 批量拉 raw；`get` 主要确保一个 raw file 可用 |
| 查询 | CLI 与服务端有结构化 search/grep/table query，结果直接给出 get 参数 | 查询主要由 Agent 消费本地 cards；没有对等的服务端结构化 search CLI |

ReIndex 当前优势是概念和主流程更短、Node 与资源角色更明确、服务端检索是一等能力、精确 get 不要求用户理解内部 UUID/package/服务端结构，并且 source 集合和哈希在 push 边界严格校验。当前不足是没有 Loom 已有的本地 Git revision、status/confirm、增量/去重上传、冲突与协作语义、批量 raw pull、Python 数据 API和成熟的 chat intent；同步 ZIP push 对超大 Collection 的带宽、超时和失败恢复也较弱。这些不足与本次明确暂缓的版本、协作和可靠性范围一致。
