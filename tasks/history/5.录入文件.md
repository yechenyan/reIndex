## 实施结果

已完成独立的 `packages/cli`，提供 `rei` 与 `reindex` 两个等价入口：

```text
rei create <collection-dir>
rei inspect <path>
rei scan <path> [--collection-root <collection-dir>]
rei check <path>
```

- `create` 建立 `.rei/collection.json` 稳定 Collection 身份，不执行扫描。
- `inspect` 只读解析最近的 Collection、`reIndex.md`、有效输入 profile、关系、变化和输出位置，供 Agent 调用。
- `scan` 通过 8 个逻辑阶段完成发现、增量解析、Node 组装、staging 校验、原子发布和状态提交。
- `check` 不重建 package，检查输入是否过期、资源 hash 和 CLI 拥有的 Node frontmatter。
- PDF 只使用 Docling；有文本层时关闭 OCR，只有无有效文本时才用 Docling OCR 重试。
- `reIndex.md` 是唯一 authoring manifest，支持 `parse.text/tables/images: auto|off`。
- CLI 拥有 Node frontmatter；Agent/curator 直接编辑现有 Node card body，后续 scan 按稳定 Node ID 保留。
- Collection 根级独立普通 Node 的文件名不编码 `order`；PDF/document group 内的有序 children 保留五位前缀。
- 没有拆出 core，也没有启动 Codex CLI 子进程；Agent 在对话中按 skill 调用确定性的 CLI。

`testbase/test2` 已生成真实 package：Collection ID 为
<id>，共 7 个 Node，包括 3 个 table Node。PDF 第 1–4 页相邻章节
合并为一个 text Node，地图保持独立 image Node；两份外部表格通过 `part_of` 和第 5 页 locator 关联，并带
Docling 生成的视觉参考，PDF 正文不重复第 5 页表格。
