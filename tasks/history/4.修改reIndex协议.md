## 实施范围

- 服务端只保存 Collection 当前态，不保留 revision 或历史版本。
- 以 `collections/nodes/resources/node_resources` 为四张核心业务表。
- 本地内容寻址目录保存所有原始文件、Node card、content 和 assets，通过 `REINDEX_DATA_DIR` 配置。
- `search_units`、向量数据和 ParadeDB BM25 为可删除重建的派生投影。
- 服务端只接受 `reindex/node@1.0`，不保留旧 loader、旧 schema 或兼容分支。
- 保留 FastAPI 工程壳和仍适用的检索能力，重写领域、导入、存储和持久化实现。

## 实施结果

- 用破坏性 baseline 重建 PostgreSQL schema，核心业务表为
  `collections/nodes/resources/node_resources`，彻底移除 revision、旧 blobs/raw_files 和兼容 ALTER。
- resource 字节继续使用本地 `FileStore`，按
  `REINDEX_DATA_DIR/objects/sha256/<两位>/<两位>/<完整 hash>` 内容寻址；数据库保存逻辑路径和引用关系。
- Node 不保存 children 数组；直接 children 使用复合索引，完整子树使用 `tree_path uuid[]` GIN，
  `order_path integer[]` 保持 package 顺序。Browse 增加 `recursive=true`；Postgres browse/get 使用定向 SQL，
  不再把完整 Collection 或 search units 加载到进程后过滤。
- card/source/content/asset 全部统一进入 `node_resources`；card 原始字节和解析后的 Markdown 分别保存。
- importer 只接受含唯一 Collection 目录的 `reindex/node@1.0` ZIP，验证树、order、URI、hash、
  assets ordinal 和 CSV schema/row count，并拒绝 traversal、symlink、重复 entry 和未引用文件。
- 每次导入在校验、文件落盘、切块和 embedding 后，用一个数据库事务替换当前态；失败导入保留并可继续
  查询之前的 Node 数据，同时在 Collection 状态记录失败原因。
- ParadeDB 使用单张 `search_units` 表和一个 BM25 index；Evidence 区分
  `card/content_text/table_row`。向量移入 `search_embeddings`。
- DuckDB 查询只把目标 CSV 复制进内存 `data` 表，关闭 external access，并限制内存、线程、结果行数。
- 恢复根 workspace 已声明但缺失的最小 `packages/cli`（`rei/reindex doctor`），使锁文件和全量测试
  可以在全新环境安装运行；编译工作流仍属于任务 5 范围，未在本任务实现。
- Render 未执行部署。Blueprint 仅为未来部署保留本地持久盘配置，并将 `REINDEX_DATA_DIR` 指向挂载点。

## 重要决定

- 按追加请求不使用 S3；当前和生产设计都使用本地内容寻址文件目录。
- 不做历史版本管理；`package_hash` 只用于当前包身份和游标失效，不保存历史。
- 保留独立 Collection 表，不使用 `is_collection`；Collection ID 等于根 Node ID。
- `resources` 表表示 Collection 内逻辑文件；相同字节复用物理对象 key，但不同逻辑路径可以有独立记录。
- 表格定义保存在 Node attributes，不建立 table catalog 或业务行表。
