# PDF 表格提取 Workflow 重做

## 用户原始请求（2026-08-04）

重新制作 `reIndex/packages/pdf-extractor-pdf`。这是一个依靠 AI 和固定代码的 workflow：

1. 主 Agent 读取和澄清需求；只有缺少影响结果的必要信息时才询问，然后生成 `job.yaml` 和任务指令。
2. 初步解析：PDF 哈希、全部页面低分辨率缩略图、Contact Sheets，以及尺寸/旋转/文字量。
3. 找表和冻结 Inventory：找表 Agent 检查所有页面，逐页输出 `table/no_table/continuation/uncertain`，生成逻辑表和 Segment，初判跨页归属；代码检查页面覆盖和结构。只提升可疑页分辨率，直到无遗漏、uncertain 和无效 Segment，再通过硬门 1。
4. 为冻结 Segment 生成高清裁剪和几何证据，两路独立生成：提取 Agent 按版式组编写代码、Segment 规则和 Merge Policy；QA Agent 独立看源截图，确认表头、列数、分段行数，并记录前两行、后两行、中间行和跨页边界样例，冻结 `reference.json`。
5. 执行、合并、比对：沙箱运行 extractor，逐 Segment 提取并实际完成去重表头、去页脚、跨页断行和顺序合并，保留行级来源页/BBox；固定 Validator 比 reference，以面向主 Agent 的 `review.json` 提供问题截图、同行对照、单元格差异和连续性合并候选。
6. Review 和局部修正：按错误类型批量路由给提取 Agent、QA Agent或高清证据；不能判断时由主 Agent看报告与源图裁决。若确认应合并，重新打开相关 Inventory、修改逻辑表/Segment 归属、重新冻结受影响项并重跑。
7. 全部通过且无高置信合并候选时生成最终交付物，通过硬门 2。

输入是人要求 AI 提取某个 PDF 的表格。输出必须在项目文件夹而非 package：`output/` 放生成表格；`extractor/` 集中放 `main.py` 统一运行/检查入口、其他代码和 `evidence/` 中间截图/报告/子 Agent 输出/计时。

实现后调用 `gpt-5.6-terra` 子 Agent，以 `testbase/test5-table/sws-netze-solingen-2024` 为项目目录处理其中 PDF。收集优化建议、每步耗时、Agent Token 和对话次数，并报告卡点、多余/缺失步骤以及降低时间、提高质量的建议。
