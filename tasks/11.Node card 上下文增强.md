# Node card 上下文增强

## 状态

进行中

## 用户原始请求

> reIndex/packages/cli 这里面生成的 node.md 目前信息有点少。 可以参考下 loom 里面的 datacard 是怎么处理生成的。不仅 PDF ，现在文本生成的描述也有点简单，你可以搜下 cluade 关于这方面的文章，要提炼这段讲什么，这段处于整个文章的什么位置。 从 pdf 生成出的表格，图片也要描述这个表格，图片在文章是什么用的，增加信息，不然孤立的数据没法建立整体。 先不要改代码，先说方案。

## 方案确认后的约束

- 文本边界完全由确定性程序决定，AI 不参与拆分。
- 文本 AI 摘要保持客观，不限制内容要点数量，但避免重复和空泛内容。
- 表格把程序计算的类型、缺失率、唯一值、min/max 等统计写进 Markdown。
- 表格允许 AI 客观介绍内容、与其他表格的明确关系及文中作用，但不评价、不分析趋势。
- 图片第一版不做复杂视觉解析，只保留 caption、文档位置、尺寸、已有 OCR 和邻近正文等轻量信息。
- 文档级批量处理，避免逐 Node 调用；未变化内容复用缓存。
- 目标是让 Agent 不读完整原始文档即可定位、理解并决定是否继续读取具体 content/raw，而不是生成冗长报告。

## 实施范围

- 改进 PDF 文本的确定性章节拆分和结构位置信息。
- 丰富 CSV/PDF 表格的确定性 profile 与 Markdown card。
- 为 PDF 图片补充轻量来源上下文。
- 更新 ReIndex scan skill，使 Agent 对同一文档的文本和表格做一次批量、客观策展。
- 保持 `reindex/node@1.0` 协议、CLI 参数和现有人工 Markdown 保留机制兼容。

## 验收

- 生成的 PDF 文本不再以固定 20,000 字符聚合成无语义的 `Document text — Part N`。
- Text card 包含客观内容说明和程序生成的章节/页码位置。
- Table card 包含紧凑字段统计和真实 Preview。
- Image card 不调用视觉模型也能说明来源文档中的结构位置。
- Agent skill 明确按文档批量策展、禁止趋势分析和主观评价。
- 新增与现有相关测试通过，未覆盖工作树中的无关修改。
